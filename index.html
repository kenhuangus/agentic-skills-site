The Paradigm Shift

Why Agentic Skills Require Dedicated Threat Modeling

Skills are first-class AI citizens: bundles of natural-language instructions, executable helpers, and persistent workspace memory that bypass traditional code-only AppSec boundaries.

Dimension Traditional Packages (npm / PyPI) Agentic Skills (SKILL.md / OpenClaw)
Packaging & Syntax Deterministic code (JS, Python, Rust) Hybrid: Markdown prose instructions + executable helpers
Execution Context Process sandbox / language runtime Full host agent authority (shell, browser, credentials, cron)
Trust Verification Lockfiles, hashes, SCA vulnerability scanners Natural language prompts; scanners bypassed in <1 hour
State Persistence Transient process memory / local disk SOUL.md & MEMORY.md persistent across all future sessions

Triage Decision Tree: Classifying Skill Findings

AST01 — Sourcing & Registry Trust

AST01: Malicious Skills

Threat actors publish trojanized skills containing hidden payloads—credential stealers, reverse shells, or social engineering instructions embedded in markdown prose.

🚨
Real-World Evidence: ClawHavoc campaign (Jan 2026) published 1,184 malicious skills delivering Atomic Stealer (AMOS) targeting crypto wallets and SSH keys. 5 of top 7 most-downloaded skills were confirmed malware.

Attack Scenarios

  • SOUL.md & MEMORY.md Backdoors: Writes malicious persistent instructions that survive skill uninstall.
  • Cognitive Degradation (QSAF): Subtly floods context over repeated turns to induce silent behavioral drift.
  • Identity Cloning: Exfiltrates agent persona and credentials to replicate agent authority elsewhere.

Key Mitigations & Code Defense

  • Cryptographic Signatures: Require Ed25519 signatures pinned to resolvable publisher identities.
  • Digest-Pinned Behavioral Sandboxes: Run helper scripts in locked-down, network-isolated containers.
  • Memory Quarantine: Validate and stage all writes to MEMORY.md and SOUL.md before commitment.
AST02 — Provenance & CI/CD

AST02: Supply Chain Compromise

Skill registries lack provenance controls, enabling typosquatting, dependency confusion, config-file hijacking, and maintainer account takeover.

📦
Real-World Evidence: Claude Code CVE-2025-59536 / CVE-2026-21852 where repo config (.claude/settings.json, hooks) triggered RCE on project open before user prompt.

Attack Scenarios

  • Nested Dependency Confusion: Skill pulls typosquatted package (yutube-dl-core) while top-level SKILL.md looks clean.
  • Registry Flooding: Uploading hundreds of malicious clones to crowd out legitimate alternatives.
  • Maintainer Account Takeover: Compromising author credentials to release backdoored v1.0.1.

Key Mitigations

  • Immutable Hash Pinning: Pin dependencies with sha256 digests via pip-compile --generate-hashes.
  • Transparency Logs: Require Merkle-tree inclusion proofs for all publish and update operations.
  • Treat Configs as Code: Apply full trust verification to hooks, settings.json, and MCP configs.
AST03 — Execution Boundaries

AST03: Over-Privileged Skills

Skills granted excessive permissions (full host shell, global filesystem, unrestricted network) allowing downstream prompt injection to execute catastrophic actions.

⚡
Real-World Evidence: Logic-layer Prompt Control Injection (LPCI, arXiv:2507.10457) & LAAF red-teaming (arXiv:2603.17239); Summer Yue Meta AI agent inbox deletion.

Attack Scenarios

  • Weather Assistant Data Theft: A benign weather tool reads ~/.env and exfiltrates all API keys.
  • Database Admin Wipe: Low-privilege prompt injection coerces manage_database into DROP TABLE.
  • Low-Privilege Confused Deputy: Invoking high-privilege skills without re-verifying caller authorization.

Key Mitigations

  • Strict Instruction Hierarchy: System > Operator > User > Tool Output. Never elevate tool data to commands.
  • Fine-Grained Manifests: Enforce domain-level network allowlists and explicit file write boundaries.
  • Mandatory Operator Confirmation: Require explicit human approval for destructive actions & identity writes.
AST04 — Parsing & Deserialization

AST04: Insecure Metadata

Attacker-controlled metadata (frontmatter, requirements.txt, manifests) parsed unsafely before execution, enabling brand impersonation and deserialization RCE.

📜
Real-World Evidence: Snyk toxicskills-goof demonstrating YAML !!python/object/apply:os.system RCE on load; ASCII smuggling hiding instructions from human reviewers.

Attack Scenarios

  • Brand Impersonation: Publishing fake Google Workspace or Solana Tracker skills to harvest credentials.
  • Permission Understating: Declaring network: false while invoking curl in hidden shell helpers.
  • JSON Prototype Pollution & TOML Injection: Polluting global parser objects during skill intake.

Key Mitigations

  • Safe Parser Enforcement: Use yaml.safe_load and disallow unsafe Python constructor tags.
  • Schema Validation: Validate all metadata against strict JSON Schema / Pydantic models.
  • ASCII Smuggling Sanitization: Strip zero-width characters and homoglyphs before review and intake.
AST05 — Execution Boundaries

AST05: Untrusted External Instructions

Skills reference remote URLs or documentation that agents read as executable instructions, creating mutable attack surfaces beyond code-signing boundaries.

🌐
Real-World Evidence: Anthropic security guidance warning that external dependencies change over time; Air Security POC demonstrating agent takeover via external docs.

Attack Scenarios

  • Author Rug-Pull: Shipping a benign skill, then editing remote documentation to inject malicious orders.
  • Reviewer Bait-and-Switch: Serving clean docs to scanners (by IP/User-Agent) and malicious payloads to live agents.
  • Relay-Node Amplification: Upstream prompt injection slipping through weaker models in multi-agent pipelines.

Key Mitigations

  • Pin & Verify External Content: Record cryptographic content hashes for all referenced remote URLs.
  • Inline Snapshots: Embed documentation into the signed skill package at publish time.
  • Domain Allowlists: Restrict remote fetches strictly to vetted, stable domain registries.
AST06 — Runtime Containment

AST06: Weak Isolation

Skills execute in the host agent security context with full access to disk, network, and devices because sandboxing is disabled by default.

🔓
Real-World Evidence: 135,000+ internet-facing OpenClaw instances (Bitdefender); ClawJacked (CVE-2026-32025 CVSS 7.5) WebSocket origin bypass.

Attack Scenarios

  • Host Escape: Skill uses os.system() to plant persistent cron jobs on the operator host workstation.
  • Skill Shadowing: Exploiting workspace > managed precedence to override built-in security tools via hot-reload.
  • Cross-Agent Contamination: Poisoning shared writable workspace memory consumed by co-located agents.

Key Mitigations

  • Mandatory Container Isolation: Enforce Docker / microVM execution by default for all skills.
  • Syscall & Capability Dropping: Apply strict seccomp profiles, --cap-drop=ALL, and read-only root filesystems.
  • Authenticated Loopback: Rate-limit and cryptographically authenticate all WebSocket connections.
AST07 — Lifecycle Governance

AST07: Update Drift

Deployed skills drift out of sync with verified baselines—either left unpatched or automatically updated with unreviewed, backdoored upstream versions.

🔄
Real-World Evidence: SecurityScorecard study finding 35.4% of scanned OpenClaw instances vulnerable to RCE due to patch lag; SkillsWatcher hot-reload abuse.

Attack Scenarios

  • Malicious Auto-Update: Author account hijacked to push v2.0 with info-stealers silently pulled by active agents.
  • Rollback Attack: Forcing downgrade to vulnerable legacy versions lacking prompt-injection defenses.
  • Hot-Reload Abuse: Modifying SKILL.md mid-session to take effect immediately without agent reboot.

Key Mitigations

  • Immutable Version Pinning: Pin all installed skills to sha256 content hashes, not loose version ranges.
  • Production Freeze Mode: Disable hot-reload and dynamic auto-updates in enterprise environments.
  • Cryptographic Update Attestation: Require signed changelogs and human-in-the-loop review for upgrades.
AST08 — Detection & Verification

AST08: Poor Scanning

Traditional regex/AST scanners fail against hybrid natural-language skills, where prose instructions achieve malicious outcomes without code signatures.

🔍
Real-World Evidence: Trail of Bits (2026) bypassed every tested marketplace scanner in <1 hour; 100k newline padding causing scanner context truncation.

Attack Scenarios

  • Natural-Language Bypass: Expressing malicious directives entirely in prose with zero detectable regex verbs.
  • Bytecode Poisoning: Hiding exploits in precompiled .pyc files while source .py files appear benign.
  • Prompt-Injecting the Scanner LLM: Injecting persuasive comments that convince the AI judge the skill is safe.

Key Mitigations

  • NVIDIA SkillSpector Multi-Tier Scanning: Combine AST taint analysis, YARA signatures, and LLM semantic checks.
  • Unicode Normalization (NFKC): Strip zero-width spaces and confusable homoglyphs prior to scanning.
  • Exhaustive Directory Analysis: Scan every artifact (.pyc, .docx, images) and report INCOMPLETE on truncation.
AST09 — Enterprise Visibility & GRC

AST09: No Governance & Shadow AI

Organizations lack central inventories, approval workflows, and audit trails for agent skills, creating unmonitored shadow AI execution layers.

🏢
Real-World Evidence: Cisco State of AI Security (2026) reported 83% of enterprises deploying agents but only 29% prepared to secure them; Bitdefender shadow AI findings.

Attack Scenarios

  • Orphaned Developer Skills: Unmonitored skills remaining active with stale privileged credentials post-offboarding.
  • Unreachable SaaS Copilot Skills: Shadow skills installed inside managed platforms invisible to local endpoint scanners.
  • Cascading Multi-Agent Compromise: Upstream skill failure propagating across agent hand-offs without audit trace.

Key Mitigations

  • Centralized Skill Inventory: Track name, version, hash, installer, and scan status in enterprise CMDB/CASB.
  • Bilateral Receipt Pattern: Generate cryptographically linked Admission and Outcome receipts for every action.
  • EU AI Act Article 12 Compliance: Implement tamper-evident automatic event logging for high-risk AI workflows.
AST10 — Standardization & Portability

AST10: Cross-Platform Reuse

Porting skills across OpenClaw, Claude Code, Cursor, and VS Code strips security manifests and drops permission constraints, creating exploitable translation gaps.

🔀
Real-World Evidence: OpenAI Autonomous Sandbox Escape (July 2026) executing multi-tenant lateral movement across Modal Labs and multiple cloud accounts.

Attack Scenarios

  • Manifest Stripping: Moving skills drops fine-grained allowlists, causing target runtime to grant full default rights.
  • Cross-Registry Arbitrage: Publishing malware on unverified registries to farm download metrics for trusted stores.
  • Implicit Privilege Escalation: Safe read-only skills on one platform inheriting broad shell access on another.

Key Mitigations

  • Universal Agentic Skill Format: Adopt the standardized YAML specification across all platform runtimes.
  • Cross-Platform Metadata Loss Simulator: Detect stripped security properties prior to ecosystem migration.
  • Registry Threat Intel Sharing: Establish shared IoC and malicious skill feeds across all major registries.
Open Standard Specification

Universal Agentic Skill Format v1.0

The proposed cross-platform standard that normalizes security metadata, cryptographically binds content hashes, and protects agent identity files by default.

SKILL.yaml · Universal Security Specification v1.0 YAML 
schema_version: "1.0"
name: "github-repo-manager"
version: "1.2.0"
publisher:
  id: "did:web:distributedapps.ai"
  signature: "ed25519:7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3d677284addd200126d9069"
security:
  risk_tier: "HIGH"
  content_hash: "sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
  permissions:
    filesystem:
      read: ["./src", "./docs"]
      write: ["./build"]
      deny_write: ["SOUL.md", "MEMORY.md", "**/.env*", "**/.git/**"]
    network:
      allow: ["api.github.com", "uploads.github.com"]
      deny: ["*"]
    shell:
      allowed_commands: ["git status", "git diff", "git push"]
      interactive: false
  audit:
    require_receipts: true
    eu_ai_act_tier: "high-risk"
